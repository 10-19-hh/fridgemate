작업일: 2026-09-28. 전용 작업트리: `prd-v2-recovered-20260919`.
기준 커밋: `b6e3f10480df1cddf9ff005b44f99698befe4c86`.
시작 상태에는 앞선 리팩토링·안정성·AT-18·사용량 정정의 미커밋/미추적 93파일이 포함된다.
이전 `../prd-v3-correction-evidence-20260928` 보관본은 수정하지 않는다.

## 구현 범위

- 홈의 첫 행동을 실제 `/meal-plan` 링크인 ‘이번 주 식단 만들기’로 제공한다. 재고 로딩 중에도
  진입할 수 있으며 로그인·재료 전체 등록을 선행 조건으로 추가하지 않는다.
- 직접 입력과 조건부 OCR 진입은 보조 행동으로, 공개 재료별 탐색·메뉴 하나 골라보기는
  기존 화면에서 유지한다. 재방문자의 유통기한·추천 표시와 순서도 유지한다.
- 주간 식단에서 미등록 재료를 ‘미보유’로 단정하지 않고 ‘구매 또는 보유 확인 필요’로
  구분한다. 일치한 재료명도 실제 충분량을 뜻하지 않으며 별도의 수량 확인을 안내한다.
- 장보기·일정 변경의 수량은 ‘등록된 재고 기준 추가 필요량’으로 설명한다. 등록되지 않은
  물리적 재고까지 확인했다는 뜻이 아니다. 숫자 계산, 확인된 0, 미확인 ‘2팩’, 원문량,
  조리 완료된 기록의 역사적 표시를 변경하지 않는다.
- 개인 식단 화면은 계속 noindex이며 공개 탐색은 가입 없이 이용할 수 있다. 새 의존성·
  상태 관리·효과를 추가하지 않고 기존 녹색/흰색/슬레이트와 타이포그래피를 유지한다.

추천 점수·별칭·카탈로그·배분 계산·DB 스키마·저장 동작·OCR 파서는 변경하지 않는다.
이번 변경만으로 FR-00의 재시도 중복 저장 방지까지 모두 완료됐다고 판단하지 않는다.

  정상이며 행 부재가 아니라 양·단위 없는 미확인 상태를 검사해야 한다. 직접 입력의 기존
  내비게이션 이름도 ‘직접 입력’이 아니라 ‘추가’다. 이후 의도적으로 등록한 재료의 수량

이 단계는 구현 4파일(HomePage·MealPlanEditor·MealPlanShoppingPreview·MealPlanChangePanel),
단위 검사 4파일, 브라우저 6파일, 문서 3파일로 총 **17파일**이다. 앞선 작업까지 포함한
미커밋/미추적 소스·문서는 99파일이다. 이전 93파일 중 의도적으로 확장한 11개를 제외한
82개는 내용 해시가 같으며 이전 전체 상태도 별도 보관한다. 원본 루트에는 쓰지 않았고
변경 목록 해시가 시작 상태와 같음을 확인한다. 이는 원본 모든 파일의 내용 해시 대조가 아니다.

영구 로컬 근거는 `../prd-v3-first-plan-evidence-20260928`이다. 기준 커밋·99파일 manifest·
소스 archive·tracked patch, 이전 93파일 archive·manifest, 유효/무효 RED·중간/최종 JSON,
로그·모바일 이미지·실제 테스트 목록 대조를 포함한다. `.env`·비밀키·사용자 DB·의존성은
보관하지 않는다. 최초 브라우저 실패 아티팩트도 별도로 남기며 통과 결과에 섞지 않는다.

않는다. 머신·의존성 스냅샷은 아니므로 동일 Node/설치 의존성 환경은 별도로 준비한다.
