## 결론

제품 방향은 일치하지만 **현재 구현이 v3의 모든 요구를 충족하는 것은 아니다.**
주간 저녁 → 장보기 → 실제 입고·조리 → 남은 식단 조정이라는 순서는 유지한다.
새 PRD의 §3은 과거 커밋 `986051a`를 설명하므로, 거기에 미구현으로 적힌 항목을
현재도 미구현이라고 취급하거나 이미 구현한 B1~B4를 처음부터 다시 만들지 않는다.
실제 배포 상태는 이번 작업에서 확인하지 않았다.

사용자 요청은 요구사항 대조와 리팩토링이다. 첨부 문서 안의 개발·운영 제안 전체를
즉시 구현하거나 자동 배포하는 승인이 아니다. 기존 [v2 진행 이력](PRD_V2_PROGRESS.md)은
과거 근거로 보존하고, v3와의 차이는 아래에서 별도로 관리한다.

### 동작 변경으로 따로 처리할 항목

1. **지난 미완료 끼니(§10.2, AT-18).** 현재 `allocateMealPlanInventory`는
   `planned`이고 날짜가 오늘 이후인 슬롯만 배분한다. v3는 조리·건너뛰기·새 날짜 이동을
   확인할 때까지 지난 미완료 슬롯의 배분을 유지하도록 요구한다. 확인 필요 표시,
   배분 보류, 지난 슬롯 이동, 여러 주의 중복 방지까지 함께 설계·검증해야 한다.
2. **실제 사용량 정정(§10.2).** 현재 취소 기능을 차례로 누르는 것은 원자적 정정과 다르다.
   기존 소비 역반영과 새 소비 저장이 모두 성공하거나 모두 취소되는 별도 작업이 필요하다.
3. **첫 진입/미등록 재고(FR-00).** 빈 재고로 생성되는 것만으로 첫 진입 전체가 완성됐다고
   판단하지 않는다. 홈 진입 행동과 ‘미보유’ 문구도 실제 정보 상태에 맞춰 검토해야 한다.

위 세 항목은 이번에 몰래 변경하지 않았다. 특히 현재 배분 결과에 새 정책의 기대값을
섞거나, 기존 테스트를 지워 v3 준수로 표시하지 않았다.

## 이번 리팩토링

### 편집 화면과 페이지 연결 분리

`MealPlanPage.jsx`는 계정/주차, 저장 hook, 조리·일정 변경·장보기 패널 연결을 담당한다.
편집 상태·이벤트와 끼니/확정본 표시는 `components/mealPlans/MealPlanEditor.jsx`로
함께 옮겼다. 페이지는 355줄에서 103줄로 줄었다. 표시 컴포넌트는 모듈 수준에 유지하며 상태 초기화·계정/주차 `key`·props·
문구·이벤트 순서·초점 복원을 바꾸지 않는다. 짧은 날짜 표시는 `mealPlanDisplay.js`를
공유한다. 범용 상태 관리 계층이나 새 의존성을 추가하지 않는다.

### 파일럿 규칙 중복 제거

동의·시작 시 정리·내보내기·오프라인 집계에 중복된 UTC 시각 파싱을
`mealPlanPilotPolicy.js`로 모은다. 로컬 35일 정책과 동의 세대의 난수 생성도 공유한다.
모듈별 오류 문구·예외 경계는 그대로 유지한다. 2000~2099년의 밀리초 포함 UTC 형식,
실제 존재하는 날짜, 정확한 만료 시각, 저장 순서·삭제 범위는 바꾸지 않는다.
서로 의도가 다른 손상 데이터 처리나 계정/탭 보호 로직은 억지로 합치지 않는다.

## 검증 방식

먼저 변경 전 전체 **190파일 2,204개**를 새로 실행해 통과했다. 기존 테스트로 동작이
보호되는 상태에서 TDD의 GREEN → REFACTOR → GREEN 단계를 적용했다. 신규 기능의
RED를 재현했다고 주장하지 않으며 기존 기대값·테스트 수·제한 시간을 바꾸지 않는다.
파일럿 관련 기존 5파일 **204개**를 공통화 직후 다시 통과했다.

최종 전체 단위·통합 **190파일 2,204개**, 브라우저 **11파일 52개**, 린트·빌드 및 공개
정적 경로 **113개**가 통과했다. 기준선과 최종 실행 대상 파일·검사 구성은 같고
skip/todo·브라우저 재시도는 없다. 원시 검사명 대조는 기존 서버 검사 1개가 `new Date()`를
이름에 포함해 처음에는 불일치했다. 해당 테스트 소스 불변을 확인하고 실행 시각 표시만
구분해 대조했으며 나머지 검사명은 동일하다. 편집기 관련 4파일 41개도 따로 통과했고, 이동한
상수/함수/화면 7개 구간을 원문과 대조해 import/export 외의 변경이 없음을 확인했다.
독립 읽기 전용 코드 검토에서도 정책·오류 처리·난수 호출·저장 순서 변경을 찾지 못했다.

기존 형태의 React `act(...)` 경고는 남아 있다. 변경 전 전체 실행에서도 경고가 있었으며
이번 작업에서 이를 숨기거나 경고 없이 통과했다고 처리하지 않는다. API 모드 브라우저는
응답을 모사하는 로컬 회귀 검사이지 실제 운영 서버 검증이 아니다.
실행은 전용 작업 트리, Node v24.19.0 및 기존 설치 의존성에서 수행했다.

```sh
npm run test:run
npm run lint
npm run build
npm run test:e2e -- --workers=2 --retries=0
```

서버·DB 버전·추천 점수·정량/배분/소비 정책·테스트 설정·의존성·원본 루트는
변경 범위에서 제외한다. 이번 작업에서는 커밋·푸시·PR·병합·배포를 하지 않는다.

변경 파일은 앱 8개(페이지 1개·새 편집 표시 모듈 2개·파일럿 모듈 5개)와 문서 4개로
총 12개다. 소스 아카이브·기준 커밋·파일 해시·기준선/최종 JSON·실행 근거는 저장소 밖의
인접 보관 폴더 `.worktrees/prd-v3-refactor-evidence-20260927`에 보존한다. 임시 JSON만을
유일한 근거로 남기지 않는다. 복원은 기준 커밋의 새 작업 공간에 소스 아카이브를 적용하고
해시를 확인하는 방식이며 기존 원본 루트에 덮어쓰지 않는다.

예산·공유·수익 기능은 선행 조건 없이 시작하지 않는다.
