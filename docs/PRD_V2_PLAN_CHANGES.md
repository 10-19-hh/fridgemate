# PRD v2 — 날짜 이동과 남은 식단 재조정

2026-09-19. 전용 작업 트리 `prd-v2-recovered-20260919`, 기준 커밋
`986051a6693a20e305adaff355530c5a2779774c` 위의 기존 미커밋 작업을 이어서 구현했다.
전체 PRD 완료·운영 배포·실사용 파일럿 결과가 아니다.

## 동작과 승인 경계

- 확정 식단의 **날짜 이동**은 빈 날/건너뛴 날로 이동하거나, 명시적으로 두 메뉴의 날짜를
  교환한다. 이미 있는 메뉴를 덮어쓰지 않는다. 이동 전후의 메뉴·필요량과 모든 미래 확정
  식단의 장보기를 비교한 뒤 **변경안 확정**을 눌러 적용한다.
- 날짜 이동은 다른 주에도 가능하다. 대상 주가 없으면 나머지 날이 모두 건너뛰기인 주를
  만들며 다른 메뉴를 자동 생성하지 않는다. 대상 주의 인분·제외 식품 조건과 맞지 않으면
  거부한다. 조리했거나 고정한 끼니와 지난 날짜는 이동할 수 없다.
- **이번 주 남은 식단 다시 맞추기**는 현재 주의 남은 예정 메뉴만 기존 규칙 기반 후보로
  다시 고른다. 조리 완료·고정·외식·지난 날짜는 그대로 보존한다. 후보가 없거나 메뉴가
  같으면 기존 식단을 유지하며, 변경이 없는 안은 확정하지 않는다.
- 재료 추가만으로 식단을 바꾸지 않는다. 메뉴 순위는 기존 재료명·기한·팬트리 규칙을
  재사용하며 새 점수 가중치나 정량 순위 알고리즘을 도입하지 않았다. 실제 수량의 부족·
  미확인은 별도 전체 배분 계산으로 확인한다.
- 외식·건너뛰기는 기존 초안→명시적 확정 흐름을 유지한다. 고정 끼니는 고정을 먼저 풀어야
  건너뛸 수 있다. 확정 후 해당 날짜의 예정 수요가 해제되어도 실제 재고·입고·수동 메모를
  삭제하지 않는다.
- 기존 조건 편집에서 고정 메뉴에 포함된 재료를 제외할 때는 메뉴를 지우지 않고 충돌
  초안을 유지한다. 다만 제외 재료가 남은 예정 메뉴는 확정하지 못하게 하여, 사용자가
  고정을 풀어 교체하거나 제외 조건을 직접 고쳐야 한다. 이미 조리한 메뉴·건너뛴 날의
  역사적 원문은 새 제외 조건을 이유로 수정하지 않는다.

이동/재조정 미리보기는 **저장하지 않는 메모리 안의 변경안**이다. 관련 주에 저장된 초안이
있으면 먼저 확정하도록 안내하고 임의로 버리지 않는다. 두 주 이동을 각각 저장/확정하여
수요가 잠시 중복되는 방식 대신, 한 번의 명시적 승인으로 관련 주를 함께 확정하고 이전
확정본을 보관한다. 창을 닫으면 미리보기만 사라진다.

## 저장·동시 처리

`mealPlanChangesRepository`는 재료·정량 확인·전체 주간 식단·입고/조리 이력을 같은
트랜잭션에서 읽는다. 미리보기 후 확정 시 원본 자료·기준 날짜·전체 변경안이 그대로인지
다시 계산해 대조한다. 다른 주/재고/이력 변경, 자정 경과, 변조·반복 확정은 거부한다.

확정은 관련 `mealPlans` 레코드만 같은 readwrite 트랜잭션으로 쓴다. 두 번째 주 저장이
실패하면 첫 번째 주도 롤백된다. 실제 재고·정량 확인·소비 이력·장보기 메모는 쓰지 않는다.
조리 이력과 현재 확정 슬롯을 양방향 검사하되, 이전 확정본의 역사적 스냅샷은 그대로 둔다.
삭제한 주의 정상 조리 이력이 남는 것은 허용하되 그 끼니의 수요를 다시 만들지 않는다.

비교 token에는 개인 원본 자료가 포함되므로 로컬 UI 메모리 밖의 로그·계측·서버로 보내지
않는다. 기존 계정별 저장 범위를 사용하며 DB 버전·인증·서버·의존성은 변경하지 않았다.
계정/주/대상 전환과 오래된 응답은 격리하며, 양념 입력 변경은 미리보기를 무효화해야 한다.
같은 계정에서 양념 값이 변경되어도 진행 중인 확정의 중복 조작 차단과 저장 후 화면 갱신은
유지한다. 양념 값을 A→B→A로 되돌려도 이전 비교가 부활하지 않는다.

동일 의존성을 확인해야 하며, 아카이브만으로 운영 데이터·기기 간 상태를 복원할 수 없다.
