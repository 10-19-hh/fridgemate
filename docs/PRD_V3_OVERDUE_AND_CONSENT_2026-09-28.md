# PRD v3 — 지난 미완료 끼니와 분석 철회

작업일: 2026-09-28. 작업트리: `prd-v2-recovered-20260919`.
기준 커밋: `b6e3f10480df1cddf9ff005b44f99698befe4c86`.
시작 상태는 커밋뿐 아니라 앞선 리팩토링·안정성 수정 42파일을 포함한다.
이전 보관본 `../prd-v3-stability-evidence-20260928`은 수정하지 않는다.

## 요구사항과 정책

PRD §10.2/AT-18에 맞춰 확정된 과거 `planned` 끼니도 예정 배분에 포함한다.
날짜가 지났다는 이유로 조리 기록·소비 이벤트를 만들거나 실제 재고를 차감하지 않는다.
사용자의 조리 기록, 건너뛰기 확정, 날짜 이동 확정으로만 예정 수요를 해소한다.

과거 배분 스냅샷은 저장되어 있지 않다. 현재 확인된 재고를 모든 확정 끼니의 날짜순으로
배분하여 과거 미완료 끼니부터 보류한다. 이는 당시 특정 재고 배치의 복원이 아니며,
새 입고도 오래된 미완료 끼니에 먼저 보류될 수 있다. 과거 끼니의 부족량·선택 재료는
새 구매 합계에서 제외하고 조리 여부 확인 목록으로 구분한다. 수량·과정 재료가 미확인인
과거 수요는 미래 배분에서도 낙관적인 충분 판정을 막는다.

과거 출발 슬롯은 오늘 이후 빈 날짜 또는 건너뛴 날짜로 이동할 수 있다. 과거 목적지와
과거 출발 교환은 금지한다. 상대 메뉴가 과거로 이동하면서 새 미완료 끼니를 만드는 일을
피하기 위한 이번 정책이다. 고정·완료·초안 충돌과 기존 제외 재료 검사는 유지한다.
이 세부 정책은 진행을 위한 명시적 가정이며 사용자 답변으로 별도 확정되었다고 기록하지 않는다.

## 저장과 화면 경계

- 일반 재생성·교체가 확정된 과거 미완료 끼니의 메뉴·분량·원문 재료를 바꾸지 못하게 한다.
  저장과 확정 시에도 최신 현지 날짜와 확정본을 검사한다. 아직 확정하지 않은 과거 초안은
  배분 대상이 아니므로 같은 보호 대상으로 오인하지 않는다.
- 건너뛰기 초안을 저장해도 확정본과 예정 배분은 유지된다. 명시적 확정 후 해제하며
  원본 메뉴·재료·분량과 이전 확정본은 보존한다.
- 자정을 넘긴 초안이 지난 확정 끼니와 충돌하면 자동 덮어쓰기하지 않는다.
  명시적 초안 복구는 충돌한 과거 슬롯만 기존 확정본으로 돌리고 미래 편집·유효한 건너뛰기는
  유지한다. 계정·저장 버전을 검증하고 실패하면 전체 원복한다.
- 모든 이전 주의 미완료 끼니를 발견하여 해당 주로 이동하는 읽기 전용 안내를 연결한다.
  날짜 경과·포커스 복귀에 안내를 갱신하고 오래된 배분 결과를 다시 사용하지 않는다.
- 장보기의 `overdueMeals` 확인 목록은 구매 가능한 `sources`와 분리한다. 지난 끼니 자체를
  입고 대상으로 고르거나 과거의 미확인 재료를 새 구매량처럼 표시하지 않는다. 자정 이후
  이전 구매 선택지를 재사용하지 않되 진행 중인 입고 저장과 완료 확인은 유실하지 않는다.
- 재생성 입력은 확정본과 보호 대상 건너뛰기 슬롯의 선택적 `undefined` 필드도 보존한다.
  이 보장은 IndexedDB/메모리의 구조화된 입력 기준이다. 외부 JSON 직렬화로 필드를
  제거한 입력까지 동일한 원문으로 복원한다는 뜻은 아니다. 다른 입력의 기존 JSON 투영은 유지한다.
- 전체 계정 자료 삭제는 별도의 명시적 삭제 경계다. AT-18은 삭제된 자료의 역사적 배분을
  재구성하거나 계정 삭제를 막는 기능이 아니다.

## 일반 분석 철회

일반 분석과 파일럿 동의는 별개다. 일반 분석의 전송 대기열은 동의 세대를 기억하고
실제 전송 직전에 동의·세대를 재확인한다. 철회·관련 다른 탭 변경 시 옛 세대의 대기 작업은
취소하고 진행 중 요청은 가능한 범위에서 중단한다. 재동의해도 옛 작업을 재전송하지 않는다.
저장 실패로 차단된 현재 문서는 다른 탭의 허용만으로 복구되지 않는다.

중단은 서버에 이미 도착한 이벤트 삭제를 보장하지 않는다. 인증 갱신 공유 요청이나
운영 분석 서비스의 삭제 정책을 이번 작업으로 변경했다고 주장하지 않는다.

## Web Storage 전체 접근 차단

인증 캐시와 재료 계정 범위 모듈에서 `window.localStorage` 속성 접근 자체가 던지는
`SecurityError`를 처리한다. 읽기는 미저장 상태, 쓰기·삭제는 실패 결과를 유지하며 서버
인증을 우회하거나 오래된 사용자로 로그인하지 않는다.

브라우저 시작 전 localStorage와 sessionStorage getter를 모두 차단해도 공개 화면과
게스트 재료 추가 버튼 클릭 → 새로고침 → 삭제가 동작하고 인증 요청이 없음을 검사했다.
이 검증은 IndexedDB가 정상인 조건이다. 팬트리·취향 설정의 저장 실패 안내, IndexedDB
접근 자체의 실패와 앱 전체 저장소 오류 대응까지 완료됐다는 뜻은 아니다.

`source-files.tar.gz`에는 미추적 파일까지 포함한다. 출발 상태 42파일도 별도
`starting-existing-changes.tar.gz`와 manifest로 보관하므로 기존 미커밋 변경을 복원할 수 있다.
비밀키·`.env`·사용자 DB·의존성 디렉터리는 포함하지 않는다.

복원은 원본이나 사용 중인 작업트리에 덮어쓰지 않고 **비어 있는 새 복제본**에서만 한다.

```sh
AT18_RESTORE_PARENT=$(mktemp -d /private/tmp/fridgemate-at18-restore-XXXXXXXX)
git clone --no-hardlinks --no-checkout /Users/lee/fridgemate "$AT18_RESTORE_PARENT/repo"
git -C "$AT18_RESTORE_PARENT/repo" checkout --detach b6e3f10480df1cddf9ff005b44f99698befe4c86
tar -xzf /Users/lee/fridgemate/.worktrees/prd-v3-overdue-evidence-20260928/source-files.tar.gz -C "$AT18_RESTORE_PARENT/repo"
```

이 단계 **이전** 상태가 필요하면 마지막 압축 파일만 `starting-existing-changes.tar.gz`로
바꾼다. 두 압축 파일을 같은 복제본에 겹쳐 풀지 않는다. 압축 파일 해시와 각 파일의 해시는
보관 manifest/verification으로 대조한다. 이는 소스 복원 절차이며 이번에는 실행하지 않았다.
검증에는 기존 설치 의존성을 재사용했다. 새 복제본에 비밀 환경 파일을 복사하거나 설치를
자동 실행하지 않는다. 의존성 자체와 실행 머신을 보관한 스냅샷이 아니므로 같은 의존성·Node
환경을 명시적으로 준비해야 동일 검사를 재실행할 수 있다.
