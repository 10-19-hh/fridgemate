# 5명·4주 파일럿 운영 기준

작성: 2026-10-04 KST. 목적은 **남은 재료를 활용해 주 2회 이상 집밥을 먹으려는 성인 1~2인 가구가, 이 도구로 메뉴를 정하고 실제로 조리하며 반복 이용하는지** 확인하는 것이다. 현재 모집·시작·실측 결과는 없다. 아래 수치는 이전 대화에서 제안한 3/5 기준을 구체화한 소규모 실험의 운영 초안이며, 외부 벤치마크나 통계적 시장 검증 결과가 아니다.

## 시작 전 확정

- 담당자: 서비스 운영자. 직접 모집한 5명, 같은 월요일 시작, 4주(월요일 00:00~다음 월요일 00:00 KST). 정확한 시작·종료 날짜는 실제 참가 URL 검증 후 기록한다. 시작 전에 이 문서의 기준과 후보 6개의 반복 가능성을 참가자에게 안내하고 기준 확정본을 보존한다.
- 참가 주소: **미확정**. 현재 자동 Preview의 `/pilot`은 운영 도메인으로 이동한다. 운영과 구분된 local-only Preview에 전용 설정을 실제 적용하고 원격 검증을 통과한 고정 origin을 먼저 확정한다.
- 저장: local-only + 사용자의 수동 JSON 다운로드·전달. 기록은 별도 동의/재개 이후부터이며 일반 분석 동의와 별개다. 같은 기기·브라우저·origin을 사용하고 비공개 모드/브라우저 데이터 삭제가 기록을 잃게 할 수 있음을 안내한다.
- 모집 명단의 연락처와 앱의 브라우저 가명은 별도 취급한다. 운영자는 동의받은 참가 코드 P01~P05와 수동 제출 파일을 연결한다. 계정·기기 수를 자동으로 사람 수로 간주하거나 동의 없는 이름·연락처를 JSON에 넣지 않는다.
- JSON 회수는 매주 종료 후 48시간 이내, 마지막 파일은 4주 종료 후 48시간 이내를 권장한다. 전달 채널·담당자와 내려받은 사본의 삭제 날짜는 **모집 전에 확정할 항목**이다. 앱의 동의 후 35일·다음 접근 시 삭제는 이미 내보낸 파일을 삭제하지 않는다.
- 앱을 다시 열면 `/pilot`에서 관측 상태를 확인하고 필요할 때 앞으로 기록 재개를 선택한다. 기록하지 못한 과거 행동을 복원하지 않는다. 누락이 있으면 주간 확인에서 직접 이용 여부를 별도 확인한다.

## 사전 의사결정 기준

| 항목 | 고정 정의와 판단 |
|---|---|
| 주간 실제 이용 | 해당 주에 성공한 `meal_cooked_recorded`가 있는 서로 다른 식단 슬롯 2개 이상. 판정 시점까지 취소된 조리는 제외하고, 단순 추천·확정·재고 사용량 정정은 조리 수에 더하지 않는다. 자기보고 조리 기록이며 실제 식사를 독립 확인한 것은 아니다. |
| 2주 반복 이용 | 최초 참가자 5명 중 1주와 2주에 각각 주간 실제 이용을 충족한 사람 수. 가입/활성화에 성공한 사람만 분모에 남기지 않는다. |
| 4주 지속 이용 | 최초 참가자 5명 중 3주와 4주에 각각 주간 실제 이용을 충족한 사람 수. 2주 반복 이용과 함께 보고한다. |
| 3~5명 | 2주 시점에는 예정된 4주 관측을 이어간다. 4주 시점에 지속 이용도 3명 이상이면 반복 사용자가 도움받은 흐름에 집중하고, 별도의 구독 가격 실험을 준비한다. 유료 결제나 수익 검증을 이미 달성했다고 쓰지 않는다. |
| 2명 | 애매한 결과. 재고 입력 이탈/메뉴 반복/도구 불편을 구분하고 한 가지 장애 개선 또는 범위 축소를 선택한다. 큰 기능 확장은 보류한다. |
| 0~1명 | 방향 축소 또는 추가 개발 중단을 검토한다. 대체 아이템은 이 판단 이후 별도 검토하며 자동 전환하지 않는다. |

이용이 확인된 사람·비이용이 확인된 사람·관측 불명 사람을 따로 기록한다. 철회·파일 미제출·브라우저 교체·기록 누락을 자동으로 비이용으로 바꾸지 않는다. 확인된 반복 이용 수와 불명까지 포함한 가능한 최대 수가 서로 다른 판단 구간이면 **판정 보류**로 적는다. 미제출이 있다는 이유로 분모를 줄이거나 성공 기준을 바꾸지 않는다.

현재 집계기의 `retention.rate` 분모는 첫 주 활성 브라우저 코호트이며 위 운영 기준의 최초 참가자 5명과 다르다. 그 값을 3/5 성공률로 대체하지 않는다. 시간 구간은 현재 집계기와 동일한 조리 기록 발생 주(KST)로 사용한다. 과거 끼니를 뒤늦게 기록한 경우 원래 식사 주로 소급해 옮기지 않는다.

## 이탈 원인과 보호 지표

- 교체·건너뛰기·명시적 미조리의 이유: 취향, 재료, 비용, 난이도, 일정, 반복 피로, 기타, 미응답. 이벤트 수와 이유 응답률을 함께 적고 미응답을 특정 원인으로 분류하지 않는다. 같은 사람이 여러 번 교체하면 여러 행동으로 집계되며 사람 비율과 구분한다.
- v1의 일반 슬롯 변경(고정/복귀/날짜 이동 등)에는 이유가 없다. 이를 v2의 `not_answered` 응답과 합치지 않는다. 미조리/건너뛰기는 초안에 저장된 선택이며 최종 확정·식사 사실을 자동으로 뜻하지 않는다.
- 이유 UI에 돌아오지 않은 이탈자는 관측할 수 없다. 주간/종료 확인에서 메뉴 반복, 입력 부담, 활용 불필요 여부를 간단히 질문하고 행동 기록과 별도 근거로 남긴다.
- 데이터 손실·중복 재고 차감·조리 기록 불일치가 확인되면 해당 배포의 모집/업데이트를 중지하고 수정·검증한다. 성공률을 높이기 위해 오류를 비이용으로 분류하거나 사용한 참가자를 제외하지 않는다.
- 4주 동안 신규 기능과 레시피 대량 추가는 동결한다. 파일럿을 막는 오류와 계측 누락만 수정하고 배포 ID·시간·변경 이유를 기록한다. 같은 origin을 유지하며 v1/v2 이벤트를 읽을 수 있는 호환 빌드로 업데이트/롤백한다.

## 모집 안내 초안

> 주 2회 정도 집에서 저녁을 만들어 먹는 성인 1~2인 가구 5분을 찾습니다. 4주 동안 냉장고 재료를 활용해 저녁 메뉴를 고르고 장보기·조리를 기록하는 도구를 써주세요. 메뉴 후보가 6개라 같은 메뉴가 반복될 수 있습니다. 기록은 동의한 브라우저에만 저장되고 자동 전송되지 않으며, 매주 직접 파일을 내려받아 정해진 채널로 전달합니다. 참여는 선택이고 언제든 철회할 수 있습니다. 미확인 재료량·기한·알레르기는 직접 확인해 주세요.

URL·날짜·전달 채널이 확정되기 전에는 이 초안으로 실제 모집하지 않는다. 검색 유입을 모집 전제로 두지 않지만, 기존 보고서에 검색 노출/클릭이 있었으므로 공개 사이트가 전혀 색인되지 않았다고 단정하지 않는다. 파일럿의 noindex와 공개 사이트 robots는 목적이 다르다.

## OCR 실측 절차

실제 영수증/주문 캡처 10~20장(가급적 서로 다른 판매처·촬영 상태)을 준비한다. 연락처·주소·주문번호·결제 정보는 먼저 가리고 사용 동의를 확인한다. 샘플 원본은 앱 저장소나 저장소 커밋에 추가하지 않는다.

1. 원본을 사람이 대조해 품목명·수량의 정답 목록을 작성하고, OCR 처리 전에 기준을 고정한다.
2. 같은 빌드·기기에서 사진 선택→인식→검토 흐름을 실행한다. 보정 학습 사용 여부와 초기 보정 상태를 기록하며 여러 번 실행한 최선 결과만 고르지 않는다.
3. 이미지별 정답 품목 수, 추출 품목 수, 수정한 품목 수, 미추출 품목 수, 오탐 품목 수, 이름/수량 오류, 인식 및 검토 시간을 적는다. 검토 완료 전에 자동 입고하지 않는다.
4. 추출 품목 수정률=`수정 필요 추출 품목/전체 추출 품목`; 누락률=`미추출 정답 품목/전체 정답 품목`; 오탐률=`오탐/전체 추출 품목`을 별도로 계산한다. 분모 0이면 비율을 0으로 만들지 말고 산출 불가로 적는다. 수량 미확인은 오류와 별도 기록한다.

기록 양식: `sample_code,source_type,build_id,device,correction_state,truth_items,extracted_items,edited_items,missed_items,false_items,name_errors,quantity_errors,unverified_quantity_items,ocr_seconds,review_seconds`.

현재 실제 샘플이 없어 수치·달성 기준을 작성하지 않았다. 기존 합성 OCR 단위/E2E 통과는 실제 영수증 수정률 실측의 근거가 아니다.
