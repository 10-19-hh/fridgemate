# 로컬 파일럿 보관·철회·내보내기 준비

갱신: 2026-09-27. 전용 작업 트리 `prd-v2-recovered-20260919`에서 진행했다.
이 기록은 [파일럿 계산 기반](PRD_V2_PILOT_FOUNDATION.md)의 후속이며, 실제 사용자
이벤트 수집이나 B5 전체 완료를 뜻하지 않는다.

## 사용자 결정과 구현 범위

- 자동 전송 없이 현재 브라우저에 보관하고 사용자가 직접 파일을 내보내는 방향이다.
- 동의 시작부터 35일이 지나면 다음 앱 실행에서 정리한다. 앱이 닫힌 동안 삭제할 수 없다.
- 분석 기록만 실패하면 조리·입고 성공은 보존하고 관측 누락을 표시한다. 이 결정에 맞는
  수집 연결·누락 복구는 아직 구현하지 않았으며 완전한 관측이라고 표시하지 않는다.

이번에 추가한 것은 동의 상태 저장 API, 기간 만료 정리, 철회, 엄격한 내보내기 형식과
오프라인 집계 연결이다. 동의·다운로드 화면과 이벤트 수집기는 아직 연결하지 않았다.
일반 분석 동의가 파일럿 동의를 대신하지 않으며 기본 상태는 꺼짐이다.

## 저장 경계

IndexedDB v7은 기존 여섯 저장소를 보존하고 `mealPlanPilot` 하나를 추가한다.
계정 삭제·공유기기 정리는 해당 계정의 일곱 저장소를 원자적으로 비운다.
일반 로그아웃은 파일럿 기록을 보존하며 다른 계정·게스트 자료를 지우지 않는다.

`mealPlanPilotConsent.js`는 범위와 동의 버전의 정확한 비교로 오래된 요청·중복 동의가
기간을 연장하거나 철회를 되돌리는 것을 막는다. 재동의는 새로운 난수 별칭과 빈 기록으로
시작한다. 원본 재고·조리 이력은 읽지 않으며 최초 생성 여부를 추정하지 않는다.
철회·만료 시 전용 저장소 전체를 지우고 오래된 요청을 차단할 최소 상태만 남긴다.
손상된 이벤트나 추가 행이 유효한 만료 헤더의 삭제를 막지 않도록 검증했다.

`mealPlanPilotRetention.js`는 앱 시작 시 현재 브라우저의 알려진 게스트·계정 DB를
열거하고 만료한 파일럿 자료만 정리한다. 다른 여섯 업무 저장소, 유효한 동의, 구 v6 DB는
수정하지 않는다. 열거·DB 접근은 제한 시간으로 끝나며 식별값이나 원본 오류를 로그로
내보내지 않는다. 열거를 지원하지 않는 브라우저에서는 새 동의를 허용하지 않는다.
삭제 차단·저장 장애·손상된 기간 헤더에서는 삭제를 보장할 수 없으며 다음 실행에서
재확인한다. 현재 사용자용 오류 화면은 미연결이다.

## 내보내기와 수치 해석

`mealPlanPilotExport.js`는 한 동의 기간·한 브라우저 범위만 허용한다.
계정 ID·원본 식재료·기피 식품·날짜별 식단 ID를 내보내기 항목으로 허용하지 않는다.
로그인 상태여도 여러 기기의 동일 계정을 합칠 수 없으므로 `signedInBrowser`로 표기하고
`actualAccountKpisAvailable: false`를 명시한다. 최초 생성은 미확인으로 유지한다.
내보내기 시각을 관측 완료 시각으로 덮어쓰지 않는다.

오프라인 집계는 기존 준비 데이터 모드와 구분해 `--local-browser-export`를 명시한다.
실제 다운로드 UI는 아직 없으며 이미 내보낸 파일은 앱에서 회수·자동 삭제할 수 없다.

```sh
node scripts/analyze-meal-plan-pilot.mjs --input LOCAL_EXPORT.json \
  --output NEW_REPORT.json --as-of 2026-09-27T00:00:00.000Z --local-browser-export
```

## 함께 수정한 입고 화면 문제

입고 저장이 완료되고 응답을 기다리는 사이 창에 다시 초점이 오면, 입력 화면의 오래된
결과를 폐기하면서 부모 냉장고 갱신까지 빠졌다. 실제 재고 500g·화면 0g의 실패를 먼저
확인했다. 같은 화면 작업의 저장 완료는 부모를 갱신하되 계정·화면 세대가 바뀐 응답은
계속 차단한다. 이 변경은 파일럿 수집 연결과 별개다.

## 검증과 증거의 한계

변경 전 전체 실행은 187파일 2,089개 중 2,088개 통과, 기존 조리 페이지 검사 1개가
저장 완료 안내를 기다리다 실패했다. 해당 파일은 수정하지 않았고 독립 재실행은 5개 모두
통과했다. 최초 실패 원인은 미확정이며 새 정책 실패나 해결 완료로 재분류하지 않는다.

TDD 절차에서 동의·기한 경계·철회·내보내기, 저장소 추가·정리, 입고 초점 경계 및 시작 시
정리 실패를 확인한 뒤 구현했다. 시작 시 정리 브라우저 검사는 실제 상태 불일치로 실패한
뒤 연결 후 통과했다. 테스트 삭제·skip·실패 기대값 맞추기는 하지 않았다.

2026-09-27 재개 시 이전 임시 폴더의 원시 JSON이 없어졌음을 확인했다. 위 초기 결과는
당시 도구 실행 기록에 근거하며, 사라진 원시 파일을 재구성하거나 보존했다고 주장하지
않는다. 이전 단계의 별도 `prd-v2-pilot-foundation-evidence-20260919` 보관본은 남아 있다.
현재 소스에 대한 새 검증 결과는 별도로 보존한다.

이번 최종 검증은 Node v24.19.0과 기존 로컬 의존성을 사용했다. 새로 의존성을 설치하거나
lockfile을 변경하지 않았다. 깨끗한 환경의 재설치·운영 서버·실제 모바일 기기 검증은 아니다.
단위 검사에서 React `act(...)` 경고는 남아 있지만 실패는 없었다.

```sh
npm run test:run -- --reporter=default --reporter=json --outputFile=FINAL_UNIT.json
npm run lint
npm run build
PLAYWRIGHT_JSON_OUTPUT_FILE=FINAL_BROWSER.json npm run test:e2e -- \
  --workers=2 --retries=0 --reporter=list,json --output=BROWSER_ARTIFACTS
```

최종 단위·통합 190파일 **2,204개**, 브라우저 11파일 **52개**, 린트·빌드·공개 정적 경로
**113개**가 통과했다. skip/todo·브라우저 재시도는 없다. 실제 실행 대상이 전용 작업 트리
안에 있고 다른 `.worktrees/**` 결과가 섞이지 않았는지 JSON 보고서로 확인한다.
최종 결과와 현재 커밋·푸시 범위는 [진행 기록](PRD_V2_PROGRESS.md)을 따른다.
원본 루트·추천 정책 실습·서버·의존성·기존 보관본은 변경하지 않았다.
커밋·푸시는 2026-09-27 사용자 승인에 따라 이 전용 브랜치만 대상으로 한다.
PR 생성·main 병합·배포는 이번 요청에 포함하지 않는다.
