# PRD v3 — 로컬 파일럿 화면과 실제 기록 연결

작업일: 2026-09-28. 전용 작업트리: `prd-v2-recovered-20260919`.
기준 커밋: `b6e3f10480df1cddf9ff005b44f99698befe4c86`.
시작 상태는 이전 작업의 미커밋/미추적 112파일을 포함한다. 이전 완료 보관본
`../prd-v3-correction-recovery-evidence-20260928`과 원본 루트는 수정하지 않는다.

## 제공 범위

게스트도 접근할 수 있는 `/pilot`을 Footer의 **식단 파일럿**에서 연다. 일반 분석 동의 및
서버 개인정보 내보내기와 별개이며, 동의 체크는 기본 해제 상태다. 동의하고 기록 시작,
상태 확인, 앞으로 기록 재개, 수동 JSON 다운로드, 취소 가능한 철회 확인을 제공한다.
동의 저장과 수집 시작은 별도 결과로 구분한다. 다운로드는 브라우저에 요청한 사실만
안내하며 파일 저장 완료·이미 내려받은 사본의 회수나 삭제를 보장하지 않는다.

사용자가 결정한 원칙을 유지한다.

- 브라우저에만 보관하며 자동 서버 전송·외부 분석 전송을 추가하지 않는다.
- 최초 동의부터 35일, 앱이 닫혀 있었다면 다음 실행/접근 시 세션 전체를 정리한다.
  재개·다운로드·재시도가 보관 기간을 늘리지 않는다.
- 분석 저장 실패는 실제 식단·입고·조리 저장을 되돌리거나 재실행하지 않는다.
- 현재 게스트/계정 공간만 접근한다. 계정 전환, 오래된 확인, 동의 세대 변경 뒤의
  응답은 새 화면·새 참여에 적용하지 않는다.
- 파일럿이 중지되거나 기존 참여 상태를 읽지 못하면 다른 화면에서도 상태 확인 링크를
  제공한다. 비참여자에게 참여했다고 추정한 경고를 표시하지 않는다.

`/pilot`은 로그인 제한은 없지만 개인 설정 화면이다. sitemap 113개 공개 경로에는 넣지
않으며 noindex 메타, app-shell rewrite, 응답 헤더, robots 구분을 유지한다.

## 실제 행동과 저장 결과

| 기록 | 성공 기준 |
| --- | --- |
| 생성 시작 / 생성 | 실제 생성 시도 직전 / 만들어진 초안의 저장 응답 |
| 식단 확정 | 확정본 저장 응답의 시각·revision |
| 슬롯 변경 | 실제 바뀐 슬롯만 저장 응답 후 기록. 날짜 이동은 미리보기 시각이 아닌 승인 응답 시각 |
| 장보기 계산 | 사용자가 명시적으로 요청한 계산의 완료. 자동 화면 읽기는 세지 않음 |
| 실제 입고 | 실제 수량 확인 후 반환된 원본 입고 이벤트 |
| 조리 / 소비 / 각 취소 | 실제 업무 트랜잭션의 원본 이벤트. 조리와 수량 소비를 별개로 기록 |
| 사용량 정정 | 기존 소비의 역반영과 새 소비를 한 묶음으로 기록. 조리 횟수를 다시 늘리지 않음 |

업무 콜백은 한 번만 실행한다. 저장 후 화면 재조회 실패나 계정 이동을 업무 실패로
기록하지 않는다. 시작 전 취소와 업무 저장 실패는 성공과 구분한다. 재시도가 새 요청 ID로
기존 입고/조리 결과를 받아도 **반환된 원본 ID·시각**으로 중복을 제거한다. 일반 식단 저장은
입고/조리와 같은 원장 기반 replay 기능이 아니며, 응답 유실을 전부 복구했다고 주장하지 않는다.

새 adapter는 원본 데이터 전체를 수집기에 넘기지 않고 허용된 이벤트 이름·상태·식별용 키·
시각·슬롯 수·엔진 버전만 만든다. 원본 키는 순간적인 입력이며 HMAC-SHA256의 세션별
비밀값과 용도 구분으로 가명화한다. 원본 재료명·수량·메모·OCR 원문·requestKey·sourceToken은
저장 이벤트나 내보내기에 넣지 않는다. HMAC은 익명성 또는 암호화 보장이 아니다.

## 관측 누락·재개와 저장 호환

DB v7의 기존 파일럿 저장소를 그대로 사용한다. 새 동의는 기존 v1 계약을 유지하고 명시적
재개에서 active row만 v2로 확장한다. 기존 이벤트·동의 시각·만료·가명 주체를 보존하며,
구버전 데이터가 있었다는 이유로 빈 기록으로 초기화하지 않는다. 내부 수집 상태·세대·
진행 표식·가명화 비밀값은 엄격한 내보내기 허용 목록에서 제외한다.

업무 전에는 진행 표식을, 실제 업무 응답 후에는 이벤트 묶음·중복 확인·표식 완료를 각각
하나의 파일럿 트랜잭션으로 저장한다. 업무 트랜잭션과 파일럿 트랜잭션은 분리한다.
수집기 begin/finish에는 각각 2초 한도를 두고, 늦은 DB/암호 연산 완료가 새 기록을 쓰지
못하게 한다. 동의·읽기에도 제한을 적용하되 업무 자체의 처리 시간 제한은 바꾸지 않는다.

- 새로고침이나 다른 페이지 인스턴스에서 이어 쓰면 중지 상태로 안내하고 명시적 재개를
  요구한다. 다른 탭의 단순 조회는 기존 수집을 중단하는 쓰기를 만들지 않는다.
- 재개는 앞으로의 수집을 여는 것이지 과거 행동 복원이 아니다. 이전 확인 시각·진행 중
  작업·누락 시작을 기준으로 missing 구간을 보존하고 오래된 작업 티켓을 차단한다.
- 기기 시계가 동의 시작 전으로 돌아가면 기록을 거절한다. 시계 복원 뒤에는 누락 시작을
  동의 시작 이상으로 제한하여 명시적으로 재개할 수 있다. 역행 중 행동을 소급 수집하지 않는다.
- 저장 자체가 불가능하면 우선 메모리에서 누락을 표시하고 관측 구간 확장을 막는다.
  그 상태에서 앱이 종료되면 실패 표식의 영속 저장은 보장할 수 없다. 다음 로드에서
  관측 중단 구간을 보수적으로 취급하며 완전 관측으로 간주하지 않는다.
- 동의 전에 발생했거나 수집하지 못한 원본 소비/조리의 취소는 원본을 소급해 만들어 넣지
  않는다. 연결할 원본이 없으면 그 묶음을 누락으로 처리하고 실제 업무 성공은 유지한다.
- 진행 중 작업이 있는 내보내기는 임시 missing 구간을 포함한다. 별도 작업의 확인된 성공은
  보존한다. 나중에 진행 작업까지 확인되면 새 내보내기에는 그 임시 누락이 사라질 수 있지만,
  이미 내려받은 파일은 수정하지 않는다.

기존 파일 검증은 모든 gap 내부의 이벤트를 거절했다. 이제 **missing은 일부 관측이 빠진
구간**으로 해석하여 그 안의 확인된 결과도 보존한다. opt-out/reset 안의 이벤트는 계속
거절한다. KPI의 전체 관측 판단은 missing을 여전히 불완전으로 취급하므로, 확인된 조리
한 건을 보관했다고 나머지 행동이 없었다고 계산하지 않는다.

`firstGenerationKnown: false`, `measurementUnit: browser-scope`, 실제 계정 KPI 미지원은
그대로다. 새 수집기를 연결했다고 로컬 가명을 실제 사람 수로 바꾸지 않는다.

테스트 우선으로 저장 API/화면 부재, 기존 누락 구간의 알려진 이벤트 거부, 동의 세대와

추가한 경계 검사는 최초 기능 RED와 별도로 기록한다. 브라우저 최초 3건은 `/pilot` 화면
부재로 실패했으며, 연결 후 실제 동의→생성→확정→내보내기→철회와 파일럿 쓰기 실패 시
식단 보존, 새로고침 뒤 재개를 검증한다.

### 중간 실패와 후속 수정

- `collector-red-01` 및 `actions-green-01`의 import/수집 오류는 유효한 기능 RED나
  성공 결과로 세지 않는다. `connected-01`의 사용량 취소 뒤 재고 확인 상태 기대값은
  fixture 오류로 바로잡았으며, 실제 재고 정책을 바꿔 통과시키지 않았다.
- `metrics-red`의 3개 실패는 missing 구간 안의 확인된 이벤트 거부를 재현했다.
  opt-out/reset 거부는 유지했고, 알려진 기록을 관측 누락과 함께 보존하도록 바꿨다.
- 시계 역행 뒤 복구 실패는 `collector-clock-recovery-red`로 별도 재현하고 수정했다.
  최종 저장·동의·보관 집중 검사 91개가 통과했다. 늦은 쓰기·용량 경계의 일부 검사는
  GREEN 뒤 보강한 검사이며 최초 RED로 주장하지 않는다.
- 최초 전체 검사 `final-unit-01`의 2,787개와 `final-e2e-01`의 78개는 통과했지만,
  `final-build-01`에 새 React 경고 113회가 있었다. 서버 페이지 목록에서 `/pilot`의
  컴포넌트가 누락된 것이 원인이었다. 공개 페이지 생성 실패는 아니었지만 그대로 완료하지 않았다.
- `server-route-red`의 Router context 오류는 Vitest 준비 오류다. 같은 실제 Provider들과
  서버 앱을 연결한 `server-route-red-02`에서 공개 홈의 invalid-element 경고와 `/pilot`
  렌더 실패를 재현했다. `AppServer.jsx`에 정적 import·페이지 등록을 추가한 뒤 2개 모두
  통과했다. 수정 뒤 코드 manifest를 `02`로 다시 고정하고 전체 검사를 새로 실행했다.
- 기존 Retention의 미지원 형식 사례는 `schemaVersion: 2`에서 `3`으로 옮겼다.
  이번에 active v2를 지원하기 때문이며, v2 보존·만료·잘못된 closed v2 거부는 별도로 검사한다.
  기준선 비교는 이 정확한 한 쌍만 명시적으로 매핑한다. 실행 시각이 이름에 들어가는 기존
  서버 Date 검사 1개의 시각 표기만 정규화하며 해당 테스트 소스는 변경하지 않았다.

TDD는 실패 재현과 실제 저장 경계 검증에, React 지침은 이벤트 처리·오래된 응답 보호와
명시적 페이지 import에 적용했다. 화면은 기존 디자인 체계의 색상·타이포그래피를 유지한다.
최종 모바일 390px 참여 화면과 데스크톱 누락/재개 화면을 캡처해 읽기·버튼·경고 표시를
직접 확인했다. 이는 실기기나 전체 접근성 감사가 아니다.

```sh
export PATH=/Users/lee/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin:$PATH
npm run test:run -- --exclude '.worktrees/**'
npm run lint
npm run build
npm run test:e2e -- --workers=2 --retries=0
git diff --check
```

tracked patch·실패/최종 JSON·로그·화면으로 남긴다. 비밀키·`.env`·사용자 DB·의존성은
포함하지 않는다. 복원은 기준 커밋의 **새 checkout**에 시작 또는 완료 archive 하나를

보관 스크립트는 staged-only 변경 없음, 일반 파일·작업트리 내부 경로, 최종 검사 목록 및
코드 해시를 확인한다. 원본 루트 보호 대조는 `git status` **목록 해시**이며 원본 전체 파일
내용의 변경 전 스냅샷은 아니다. 그보다 강한 불변 증명으로 표현하지 않는다. 로그·테스트
fixture를 보관하지만 이 스크립트가 범용 비밀 탐지 도구인 것은 아니다.

재현 시 `source-manifest.json`의 기준 커밋으로 준비한 새 checkout에 `source-files.tar.gz`를
풀고 모든 파일의 SHA-256을 대조한다. 이 단계 시작 상태가 필요하면 대신
`starting112-source-files.tar.gz`와 `starting112-manifest.json`을 사용한다. 두 archive를
서로 덧씌우지 않는다. 같은 Node/기존 의존성 조건에서 위 명령을 실행한다.

## 남은 전체 목표와 한계

이 단계는 로컬 파일럿 사용 준비이며 실제 참여자 결과가 아니다. 메뉴 20~30개 검수,
실기기·전체 접근성·30개 검수 조합 조건의 성능·저장 실패 QA·깨끗한 설치 CI·운영 검증,
승인 후 10~20명/4주 파일럿이 남는다. OCR 실제 인식 품질과 운영 API도 이번 결과로
검증됐다고 하지 않는다. 공개 소개·검색 유입과 후속 예산·선호·공유 등 전체 목표를 유지한다.

브라우저 저장소 삭제·기기 손실·다른 기기 사용·옛 앱 버전의 행동까지 복원하지 않는다.
WebCrypto가 없거나 기록 한도(진행 100건, 이벤트 50,000건, 누락 구간 100개)를 넘으면
수집을 중지하고 불완전성을 유지한다. 업무는 별도 저장소의 기존 실패 규칙을 따른다.
파일럿 실패 격리는 IndexedDB 자체가 사용 불가능해도 업무 저장이 성공한다는 뜻이 아니다.
커밋·푸시·PR·병합·배포·참여자 모집은 이 단계에서 수행하지 않는다.
