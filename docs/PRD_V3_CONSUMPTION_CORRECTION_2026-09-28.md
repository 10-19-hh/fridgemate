# PRD v3 — 실제 사용량 원자적 정정

작업일: 2026-09-28. 작업트리: `prd-v2-recovered-20260919`.
기준 커밋: `b6e3f10480df1cddf9ff005b44f99698befe4c86`.
시작 상태는 이전 AT-18 단계까지의 미커밋 78파일이며, 이전 보관본
`../prd-v3-overdue-evidence-20260928`의 파일 해시 78개와 모두 일치함을 먼저 확인했다.
원본 루트와 보관본을 실행 대상으로 바꾸거나 덮어쓰지 않는다.

## 요구사항과 저장 계약

PRD v3 §10.2의 300g − 실제 소비 150g + 실제 입고 500g = 650g 상태에서
150g을 100g으로 정정하면 총 보유량은 **700g**이다. 이는 과거 재고 스냅샷 복구가 아니라
현재 호환 재고에 150g을 더하고 새 100g을 빼는 작업이다. 이후 입고·메모·다른 재고는 유지한다.

- `correctMealConsumption`은 기존 `runMealCookingTransaction` 안에서 재고 원본,
  수량 확인, 식단 슬롯, 소비 이벤트를 함께 읽고 최종 상태만 저장한다. 역반영만 된 중간
  수량이 별도 commit되지 않는다. 어느 쓰기라도 실패하면 네 저장소가 모두 원복된다.
- 최초 `cooking` 이벤트와 조리 시각·사실은 불변이다. 기존 `consumption`을 지우지 않고
  `consumption-reversal`과 새 `consumption`을 같은 operationId/requestKey로 추가한다.
  새 소비의 `replacesId`, 역반영의 `replacementConsumptionId` 연결을 양방향 검증한다.
- 조회는 최초 조리 포인터에서 검증된 연결을 따라 최신 소비를 찾는다. 중간 역반영을
  최종 소비 취소로 오인하지 않는다. 조리 횟수는 정정 때문에 늘어나지 않는다.
- 정정 요청에는 최신 소비 ID, 계획 revision, 이전 소비에 포함된 모든 재고의 현재
  revision/source token, 새 사용량과 완전성 확인을 요구한다. 다른 재고를 선택하거나
  일부 행을 제외할 수 있다. 전체 0 사용도 명시적으로 확인하면 빈 새 소비 목록으로 저장한다.
- 0 사용 정정은 최초 사용량 미확인 조리와 다르다. 최초 수량 미확인 조리를 정량 소비로
  변환하거나 이미 단독 취소된 소비를 다시 적용하는 기능은 이번 정정 API가 아니다.
- 원래 사용한 재고가 삭제·소비 완료·수량 미확인이거나 이름·단위 차원·조리 상태가 달라지면
  정정을 막고 수량 확인을 요구한다. 원본 소비 기록에서 현재 재고 수량을 추측하지 않는다.
- 같은 정정의 반복/동시 요청은 한 번만 반영한다. 다른 사용량·오래된 다른 요청은
  최신 상태를 덮어쓰지 않는다. 식단 삭제 후에도 소비 이력은 남으며 재고 정정은 가능하지만
  삭제한 식단은 다시 만들지 않는다.
- 정정 후 소비 취소는 최신 소비량만 역반영한다. 조리 사실을 남긴 단독 소비 취소는 기존처럼
  남은 수량 확인이 필요하다. 사용량 0의 소비 취소는 역반영할 재고 행이 없어 재고 자체를
  바꾸지 않는다. 조리 사실 취소는 최신 소비를 별도로 취소한 뒤에만 허용한다.

추가 이벤트 종류, DB 스키마 마이그레이션, 의존성, 서버/API 저장, 일반 분석 또는 파일럿
전송을 추가하지 않는다. 원문 재고가 포함될 수 있는 requestKey/source token은 로컬 검증
자료이며 분석·로그 payload로 내보내지 않는다.

## 연결 경계

`getMealCookingState`는 한 범위의 전체 이력을 검증하여 최초 조리, 최신 소비,
최종 단독 역반영, 조리 취소 여부를 투영한다. 고아 연결·다른 범위/끼니·분기·순환·중복 역반영,
짝이 없는 정정은 거절한다. 빈 이력은 null이며, 잘못된 이력은 대상 ID가 없더라도 오류다.
이 함수는 권한을 부여하지 않는다. 호출자는 기존 게스트/로그인 계정 범위를 선택해야 한다.

정정·취소의 저장 경계와 일정 변경 경계는 슬롯의 최신 소비/역반영 포인터가 이력과
일치하는지도 확인한다. 정정 이전 미리보기는 거절하고 새 미리보기로 이동·재조정한다.
공개 카탈로그 원문·예정량·다른 끼니·유효한 미래 초안은 정정하지 않는다.

## 전체 목표에서 남은 일

AT-18과 이 정정 경로는 전체 PRD 완료와 같지 않다. 다음은 FR-00의 식단 중심 첫 진입과
미등록/미보유 구분, OCR 중복 저장·교체 원자성, 손상 보정 복구 UI다. 이후 파일럿 별도
동의·철회·수집·관측 누락·수동 다운로드를 연결하고, 검수 메뉴 20~30개와 실기기·접근성·성능·
저장 실패 QA 및 실제 10~20명/4주 파일럿 증거가 필요하다.

파일럿의 로컬 보관·수동 내보내기·35일 후 다음 실행 시 정리·분석 실패에도 조리/입고 보존
결정은 유지한다. 공개 식단 중심 소개/유입 관측, 파일럿 이후의 예산·선호 확장, 공유·공동 테마,
별도 검증 후의 수익화·영양·가구 공동 사용·기기 간 동기화도 전체 목표에 남아 있다.
커밋·푸시·PR·배포·실제 참여자 모집은 이번 로컬 구현에서 수행하지 않는다.
