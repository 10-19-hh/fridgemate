# PRD v3 — 팬트리·취향 저장 실패와 늦은 응답 보호

작업일: 2026-09-28. 전용 작업트리 `prd-v2-recovered-20260919`, 기준 커밋
`b6e3f10480df1cddf9ff005b44f99698befe4c86`. 앞선 파일럿 연결 완료본의 미커밋/미추적
138파일을 포함한 상태에서 이어 작업한다. 원본 루트와 앞선 보관본은 변경하지 않는다.

## 변경 계약

- 팬트리·취향은 로컬 쓰기가 성공한 뒤에만 추천에 사용하는 값을 바꾼다. 실패하면
  이전 추천 값·저장 원문을 보존하고 안전한 안내와 재시도를 제공한다. 로컬 쓰기가
  실패한 설정을 서버에 먼저 보내지 않는다. 브라우저 오류 원문을 화면에 출력하지 않는다.
- 읽기 실패·구조가 손상된 설정은 빈 설정과 구분하고, 원문을 자동 삭제하거나 덮어쓰지
  않는다. 명시적 재확인 전에는 편집을 잠근다. 설정 파일 복구/초기화 기능을 추가한 것은 아니다.
- 서버 저장 실패는 이미 저장한 로컬 값과 구분한다. 팬트리는 실패한 같은 상태를 다시
  저장할 수 있다. 서버가 성공 응답을 반환했지만 캐시에 반영하지 못한 취향 저장도
  전체 실패나 완전 성공으로 표시하지 않는다.
- 취향 저장의 성공 안내는 다음 저장 시도 때 지운다. 실패한 텍스트 입력은 유지한다.
  저장 중에는 입력을 잠그며, 렌더 이전의 연속 요청도 중복 전송하지 않는다.
  매운맛/조리 여유 선택의 자동 저장은 해당 항목만 저장했다고 안내한다. 아직 제출하지
  않은 선호/비선호 입력까지 저장됐다고 표시하거나, 사용자의 별도 저장 없이 합쳐 보내지 않는다.
- 상태 updater에서 저장/네트워크 부수효과를 제거한다. 계정 변경·같은 계정 재진입·
  언마운트·다른 탭의 해당 설정 변경/전체 삭제 뒤의 오래된 조회와 저장 응답은 현재
  로컬 상태에 적용하지 않는다. 다른 계정 키와 sessionStorage 이벤트는 무시한다.
- RecipesPage의 재고 있음/없음 두 팬트리 경로에 오류·잠금·재확인을 연결한다.
  접힌 설정에서도 읽기 미확인을 보유 0개로 단정하지 않는다. 기존 디자인 체계의
  색상·타이포그래피를 유지하고 오류는 alert, 저장 성공은 status로 전달한다.

DB·스키마·재료 정규화·추천 가중치·원문 메뉴·의존성·인증 정책은 변경하지 않는다.
TDD는 실제 실패 후 구현에, React 지침은 사용자 동작과 저장 부수효과의 분리에,
디자인 지침은 실패 이유/다음 행동을 기존 화면에서 구분하는 데 적용했다.

## 검증 기록

시작 전체 기준선은 **220파일 / 2,789개 통과**다. 기존 설치 의존성과 Node 24.19.0을
사용하며 `.worktrees/**`를 제외한다. 최종 전체 결과는 다음과 같다.

- `settings-red-01`: 17개 실패 중 팬트리 선택자 오류가 섞였다. 전부 유효 RED가 아니다.
- `settings-red-02`: 선택자 보정 후 정상 보호 2개 통과, 실제 저장/응답 경계 15개 실패.
- 추가 RED는 인증 상태의 로컬 실패·다른 탭·구조 손상·모델 전달 경계를 포함한다.
- 브라우저 `settings-e2e-red-01`의 팬트리 2개는 접힌 details를 열지 않은 테스트 절차
  오류다. 절차를 보정한 `settings-e2e-red-02`는 실제 오류 안내 부재 3개를 재현했다.
- 지연 ACK 브라우저 첫 검사는 화면 이동 직후, 실제 비동기 삭제 완료 전에 저장소를
  확인했다. 로그아웃 응답까지 기다리도록 보정했으며 이 실패는 버그 재현으로 세지 않는다.
- 집중 GREEN 뒤의 lint 정리는 가변 요청 정보를 React state/updater와 분리한 ref에 두며
  테스트의 렌더 중 probe 갱신을 정리한다. 테스트 기대 결과를 완화해 통과시키지 않는다.
- `settings-summary-red-07`: 기존 화면 2개 통과, 닫힌 요약의 읽기 미확인 사례 1개 실패.
  수정 후 `settings-green-08`의 집중 3파일 30개가 통과했다.
- 독립 검토에서 드롭다운의 부분 저장이 미제출 재료까지 저장한 것처럼 보이는 문제를
  발견했다. `settings-partial-notice-red-09`는 기존 26개 통과/추가 2개 예상 실패다.
  두 선택 필드만 내부 enum으로 구분하며 기존 전체 저장과 실제 저장 데이터 정책은 유지한다.
- `useUserPreferences`의 Provider 생성 줄에만 `react-hooks/refs` 억제가 있다.
  독립 검토로 ref 접근이 layout/effect/사용자 callback 내부에만 있고 Provider 생성은
  callback 참조를 전달할 뿐 호출하지 않음을 확인했다. 규칙 전체/파일을 끄지 않는다.
- 부분 저장 안내 수정 후 `settings-partial-notice-green-10`은 집중 3파일 32개 통과다.
- 최초 보관 스크립트의 닫는 중괄호 누락은 앱/테스트 실패가 아닌 도구 준비 오류였다.

## 남은 목표와 보장 한계

- 이번 범위는 설정 두 종류다. 일반 재고 읽기·수정·삭제·편집 폼의 실패 표시와 앱 전체
  저장소 장애 대응, 실제 기기 저장 공간 고갈 검증까지 완료됐다고 하지 않는다.
- 이미 서버로 보낸 요청을 취소하거나 서버 저장을 되돌리는 기능은 아니다. 공용
  `apiClient.js`의 401 재인증 후 자동 재전송에는 계정 세대 검사가 없는 경로가 있으며,
  hook의 로컬 응답 보호가 그 원격 재전송의 계정 격리까지 보장하지 않는다. 별도 재현과
  보강이 필요하다. 실제 서버·DB·외부 모델 API는 이번에 호출하지 않는다.
- 새 설치 CI는 아직 실행하지 않았다. root manifest와 lock의 직접 의존성은 일치하지만,
  기존 Prisma 생성 클라이언트를 사용하는 로컬 통과와 새 설치 성공은 다르다. root의
  client/CLI 6.19.3 및 adapter-pg 7.10.0 조합은 검증 대상이지 확인된 실패가 아니다.
  새 복제본에서 현재 CI 그대로 설치한 뒤 클라이언트 생성 여부와 전체 검사를 확인하고,
  필요할 때만 생성 실패를 분리 진단해야 한다. 원본에서 npm ci로 설치본을 교체하지 않는다.
- 메뉴 목표는 20~30개를 유지한다. 편집 16개와 식재료량 대조 6개를 완전 검수 22개로
  합산하지 않는다. 이번 원문 추가 점검도 미정량 과정 물·추가 양념 등의 문제를 남겼으며
  메뉴 데이터를 확정하거나 수량을 추측해 추가하지 않았다.
- 실기기·전체 접근성·검수 30개 조합 성능·운영 검증·10~20명/4주 파일럿은 미완료다.
  공개 소개/검색 유입, 후속 예산·선호 확장·공유·수익화 등의 전체 목표도 유지한다.
  커밋·푸시·PR·병합·배포·참여자 모집은 하지 않는다.
