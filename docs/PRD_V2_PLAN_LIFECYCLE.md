# PRD v2: 초안과 확정 식단 분리

기록일: 2026-09-15. B2의 선행 저장/화면 작업이며 재고 배분·식단 장보기의 완료가 아니다.
입력 PRD와 전체 남은 범위는 [진행 기록](PRD_V2_PROGRESS.md)에 유지한다.
이전 목표 턴은 실제 소스 대조 카탈로그·테스트·근거 자료를 추가한 진행으로 분류했다.

## 목표·변경 파일·제외 범위

초안 생성·편집이 유효 확정본을 덮어쓰지 않고, 사용자가 확정한 결과가 로컬 저장에
성공한 뒤에만 화면에서 확정됐다고 안내한다.

- 저장: `src/features/mealPlans/mealPlanRepository.js`와 해당 `__tests__/mealPlanRepository.test.js`.
- 연결: `src/hooks/useMealPlan.js`와 해당 `__tests__/useMealPlan.test.js`.
- 화면: `src/pages/MealPlanPage.jsx`와 해당 `__tests__/MealPlanPage.test.jsx`.
- 브라우저: `e2e/meal-plan.spec.js`, `e2e/meal-plan-account.spec.js`.
- 문서: README, CHANGELOG, 이 파일, PRD_V2_PROGRESS.

계산/검수 카탈로그, 기존 추천 구현·테스트, IndexedDB 버전/저장소 정의, 인증·서버·
의존성·테스트 설정은 변경하지 않았다. 재고 배분/차감, 구매·조리 이벤트, 기존 장보기
변경, 배포도 이 작업에 포함하지 않는다. 보관용 원본 루트는 수정하지 않았다.

## 저장 계약

```text
주별 레코드(schemaVersion: 2)
├─ revision: 주별 저장 작업의 순서
├─ draft: 편집 중인 식단 스냅샷 또는 null
├─ confirmed: 현재 확정된 식단 스냅샷 또는 null
└─ archives: 교체된 이전 확정 스냅샷들
```

각 내부 식단은 기존 schemaVersion 1의 원문·설정·엔진/카탈로그 버전·재료 스냅샷을
보존한다. 기록 키는 기존 `week:YYYY-MM-DD`, IndexedDB는 기존 v3의 scope별
`mealPlans` 저장소를 사용한다. 한 주에 유효 확정본은 하나다.

| 공개 함수 | 입력·결과와 권한 경계 |
| --- | --- |
| getMealPlan(weekStart, scope) | null 또는 v2 주별 레코드. v1을 읽으면 초안으로 투영할 뿐 저장하지 않음 |
| saveMealPlan(plan, scope, expectedRevision) | 현재 저장 revision과 정확히 일치할 때만 초안을 저장하고 주별 레코드 반환 |
| confirmMealPlan(weekStart, scope, expectedRevision) | 저장된 현재 초안만 확정. 기존 확정본 보관·초안 제거를 함께 저장한 레코드 반환 |

`expectedRevision`은 필수인 0 이상 안전한 정수다. 최초 저장은 0이며, 읽기·비교·쓰기
전부 같은 readwrite transaction 안에서 처리한다. 요청한 plan.revision을 크게 부풀려도
충돌 검사를 우회하지 못한다. 저장소가 새 주별 revision과 draft.revision을 할당한다.
초안 저장 시 수정 시각은 저장소 현재 시각이고 생성 시각은 기존 초안이 있으면 유지한다.
기존 초안이 없는 최초/확정 후 새 초안은 새 생성 시각을 갖는다.

확정 시 스냅샷의 revision·원문·수량 상태·시각은 그대로 보존하고, 주별 레코드의 revision과
updatedAt만 갱신한다. 따라서 스냅샷 revision과 주별 revision은 다를 수 있다.
다시 확정할 때 이전 확정 스냅샷은 archives에 추가한다. 자동 삭제/가지치기는 하지 않는다.
이 보관은 브라우저 로컬 기록이며 클라우드 백업이 아니다. 보관 기록 열람·개별 삭제 UI는
아직 없고 저장 용량이 부족하면 기존 자료를 보존한 채 저장 실패를 표시한다.

이전 v1을 조회하는 것만으로 DB 레코드를 v2로 바꾸거나 확정하지 않는다. 새 저장/명시적
확정 때 v2 레코드로 전환한다. 원문 손상·미지원 버전·다른 scope/주차·빠진 배열 항목·
주별 revision보다 큰 내부 snapshot revision을 거부한다. 기존 v1 앱은 새 v2를 미지원
버전으로 거부하므로 새 저장 형식을 구버전에서 편집할 수 있다고 안내하지 않는다.

## 화면과 비동기 상태

- 화면은 저장 응답의 `draft ?? confirmed`로 편집 대상을 계산한다. 확정본은 별도로 유지한다.
- 처음에는 `초안`과 `이 식단 확정`, 수정 중에는 `수정 초안`과 `수정 초안으로 확정본 교체`를 표시한다.
- 수정 중에도 현재 확정본의 날짜·메뉴·인원을 읽기 전용으로 확인할 수 있다.
- 설정 변경이 아직 초안에 저장되지 않았으면 확정 버튼을 비활성화한다.
- 확정은 메뉴 선택을 기록하는 단계이며 수량·식품 안전 검수 완료가 아니라고 안내한다.
- 성공은 저장 응답 이후에만 표시한다. 연속 클릭·저장 중 확정·확정 중 편집은 차단한다.
- 계정/주차/인증 컨텍스트가 바뀐 뒤의 오래된 콜백·응답은 화면에 적용하지 않는다.
- 재불러오기를 요청한 순간 쓰기를 차단한다. 같은 이벤트에서 재불러오기와 확정이 겹쳐
  로딩 효과가 저장 상태를 지우는 반례를 테스트로 재현한 뒤 보완했다.
- 확정 버튼이 사라지면 키보드 초점을 상태 제목으로 옮기고 저장 결과를 알린다.

디자인은 기존 녹색 팔레트·글꼴을 유지했다. 왼쪽 정렬 상태 줄과 필요한 행동만 추가하고,
모바일에서는 버튼을 한 줄 폭으로 제공한다. 색상만으로 초안/확정을 구분하지 않는다.

### 실행 방법

Node 24.19.0/Vitest 5.0.0, 기존 검증 의존성의 package/lockfile 일치를 확인한 뒤
`/private/tmp/fridgemate-weekly-pr-CtPuVjtR/node_modules`를 임시 링크해 사용했다.
실행 시 `/Users/lee/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin`을
PATH 앞에 지정했다. 루트의 의존성이나 `.env`를 복사하지 않았다.

```sh
npm run test:run -- --exclude '.worktrees/**' --reporter=json --outputFile=/private/tmp/fridgemate-prd-v2-lifecycle-Y6Wwui3z/final-tests.json
npm run lint
npm run build
npm run test:e2e -- --reporter=list
git diff --check
```

브라우저·정적 페이지 검증에는 로컬 포트 사용 권한이 필요하다. 실행이 끝나면 임시
node_modules 링크만 제거하며 의존성 원본은 보존한다. 다음 단위는 일치 여부를 다시
확인하고 링크를 연결해야 한다. 코드·테스트·문서는 이 별도 작업 공간의 미커밋 상태다.
commit/push/merge/배포를 수행하지 않았다.

TDD는 예상 실패 확인과 리뷰 반례 보완에, React 가이드는 저장 응답에서 상태를 파생하고
확정 행동을 이벤트 핸들러에 두는 데, frontend-design은 기존 화면의 문맥을 유지하면서
상태·효과를 구분하고 키보드/모바일 행동을 검토하는 데 적용했다.

## 남은 범위

이 작업으로 B2 전체나 P0를 완료했다고 판단하지 않는다. 여러 주의 미래 확정 식단 조회,
확인된 재고량 입력, 가상 배분, 출처별 장보기와 실제 검수된 한 끼 자료 확충이 남았다.
그 후 실제 입고/소비/취소, 날짜 이동/재조정, 최소 계측·파일럿·성능 검증으로 이어간다.
정량·가격·개인정보·사용 관찰의 선행 조건 없이 후속 예산·공유·유료화를 열지 않는다.
